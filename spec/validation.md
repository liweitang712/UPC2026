# Problem B validation protocol

# Location-first manuscript release

For the current manuscript, use the [M2 location protocol](../releases/upc2026-location-v2/protocol.json)
and [release guide](../releases/upc2026-location-v2/README.md). M2 is the
physics-motivated working forecast. Compare M2 against M1 and B0 on common
supported true plane crossings using the energy score, with paired intervals.
Report empirical coverage, region area and the total and supported crossing
counts alongside the comparison. Event Brier loss is secondary for this study.
Use a fresh holdout when the objective changes, and freeze predictions before
opening the scoring truth.

The remaining sections document the original event-first protocol. Their
selection gates apply to the archived `upc2026-wp3-v1` release.

Status: planned. This specification defines experiments and decision rules. It contains no new predictions, simulation results, or empirical performance claims.

Use [`case.json`](case.json) for the supplied kick and [`schema.md`](schema.md) for the interface, field names, units and event definitions. Names in this protocol describe data roles. The schema controls serialization. Freeze the protocol before examining blind outcomes.

## Ownership and freeze order

1. **`b_integrator`** freezes the event definitions, scenario distributions, split sizes, selection rule, and acceptance tolerances. Record them in `release.json` with the source revision or file hashes, solver settings, and separate seeds for scenario generation, observation noise, inference, and bootstrap. Use one run ID across inputs, draws, scores, figures, and manuscript evidence. Confirm stable fixture and case IDs before handing off work.
2. **`b_validation`** independently generates complete trajectories and event labels. Derive noisy input frames from those trajectories, store observations in `cases.csv` and labels in `truth.csv`, and publish development data and blind input frames. Lock blind truth, generation seeds, and case membership until predictions are frozen. Supply a checksum or equivalent immutable record for the locked split. The matched generator may share equations with the predictor and should independently implement integration and event localization.
3. **`b_physics` and `b_inference`** use only the observation interface at inference time. Tune on development cases. Submit all candidate prediction bundles for the selection split without its truth, then lock the chosen model, prespecified fallback, and configuration. Produce blind predictions before seeing blind truth. Keep all cases, including returned abstentions and numerical failures. `b_inference` owns `predictions.csv` with key `case_id, model_id, scenario_id, draw_id` and fields `weight, event, t_s, y_m, z_m, clearance_goal, reason`. Leave non-crossing coordinates blank.
4. **`b_validation`** scores locked predictions against locked labels, with joins on the schema keys. Publish `metrics.csv` and pass its verified totals to `b_integrator` for `summary.json`. Reveal blind truth only after the submission freeze. Revisions after reveal require a fresh blind split or a clear label that the affected result is exploratory.

Use a development split for debugging and tuning, a separate selection split for choosing model complexity, and a final blind split for reporting. All noise replicates of a physical shot belong to the same split. Do not tune on the supplied kick or include it in aggregate validation. Lock practical sample sizes and minimum stratum counts before any run. If a stratum misses the locked minimum, report its counts and treat its comparison as inconclusive.

## Test cases and acceptance checks

| Check | What to hold fixed or vary | Acceptance evidence |
|---|---|---|
| Analytic and event fixtures | Gravity-only solution, constant-acceleration root, upward departure from the ground, ground before plane, plane before ground, nearly simultaneous events, frame boundaries, and no forward crossing | Correct event identity and order. Analytic and step-refinement differences below 1 mm for position and 0.1 ms for time on nondegenerate fixtures. Use the schema tie rule at the event tolerance and report boundary cases separately. |
| Coordinate equivalence | Compare time-domain and distance-domain formulations of the *same* physics while forward speed stays positive. Perturb measured `x` as well as `y` and `z`. | Same event, crossing point, and arrival time within the numerical tolerances above. Treat low or reversed forward speed through the event contract. Compare different physical assumptions only after this check. |
| Inference calibration | Draw parameters from a candidate's own prior and simulate observations under its likelihood. Use randomized posterior ranks if the estimator or ties require them. Keep these checks separate from the predictive benchmark. | Inspect rank uniformity, effective sample size, and tail-weight or sampler diagnostics. Treat failures as inference defects before blind scoring. |
| Matched synthetic cases | Fixed model family with independent truth solver and blinded observation noise. Include plausible incoming angles, speeds, and spin or effective lateral force. | Report case counts, proper scores, coverage, and interval width with uncertainty. State that this measures performance under the chosen synthetic distribution. |
| Physics and sensor stress | Label single-factor and combined misspecification separately. Use prespecified strata for wind, ball type or orientation, speed-dependent drag, varying lift, and different scales or correlations of frame noise. Include in-frame shots, wide or high misses, border cases, ground-first trajectories, and physical non-crossings. | All locked cases with a valid truth label contribute to event scoring. Report stratum scores, failure counts and paired differences. Report a separate challenge stratum if intentionally over-representing rare events. Record truth-solver failures and resolve them by independent refinement before freezing labels when feasible. List unresolved truth cases and their exclusion from truth-dependent scoring. |
| Weak-identification challenge | Search for physically bounded trajectories whose first two noisy observations are statistically compatible and whose later outcomes diverge. Test prior sensitivity separately from measurement-noise sensitivity. | Record early observation separation in Mahalanobis units and later separation in metres or different outcome categories. If no pair is found under the bounds, report the search limits. |
| Optional observed trajectory | Use a public, attributable track only if kick onset, time grid, continuity, and the goal-plane reference can be checked. | Use actual timestamps and only pre-cutoff frames as inputs. Show observation and label uncertainties. Report the example separately from synthetic aggregate calibration. |

Lock all scenario weights before scoring. Give matched and each stress stratum separate rows, and use an equal-weight average across prespecified core strata for model selection unless the manifest declares a target-population mix before the run. A deliberately enriched boundary or rare-event sample measures performance for that challenge distribution. Keep it separate from any estimate of ordinary shot frequencies.

## Metrics and failure policy

For each shot, retain weights for `PLANE_GOAL`, `PLANE_WIDE`, `GROUND_FIRST`, `NO_REACH`, and `NUMERICAL_FAILURE`. Plane arrival is the union of `PLANE_GOAL` and `PLANE_WIDE`. Use the same geometric rules for truth and draws. A first turf contact belongs to a separate category because the airborne predictor does not continue through a bounce. The center-in-goal event is primary. Arrival at the plane, radius clearance, and ground-first are secondary.

- **Primary selection score.** Use all-case Brier loss for the center-in-goal indicator, \((p-I)^2\). A point abstention still receives this score if its event probability is available. For remaining unresolved draws of total weight \(f\), report the probability range \([p_{\rm known},p_{\rm known}+f]\), using the complete draw denominator and treating the unresolved draws as all outside or all inside the event. For selection, use the larger Brier loss at the two endpoints. Charge an entirely missing or invalid forecast a loss of 1. Label this aggregate failure-penalized Brier loss. Also report ordinary Brier score on exact-probability forecasts and give its denominator.
- **Secondary event checks.** Apply the same scoring rule to plane arrival, ground-first and radius clearance. Report physical non-crossing, technical failure and point abstention separately, including any fallback activation. If a method has a valid event distribution but insufficient support for a conditional statistic, retain its event forecast and leave the conditional statistic unavailable. Lock any solver retry or forecast fallback before scoring and record both original failures and final unresolved outcomes.
- **Conditional location and time.** Compare the joint conditional \((Y,Z)\) distribution with energy score in metres where truth crossed the plane and the prediction defines a plane-crossing distribution. Report a paired point RMSE as a secondary result on the same common valid cases, and publish the full truth-plane denominator plus exclusions for each method. Never fill undefined locations with a fabricated point. Report arrival-time error in seconds when both crossing times exist.
- **Calibration and sharpness.** Check nominal joint 50%, 80%, and 95% plane-crossing region coverage on true plane crossings with a defined predictive region, alongside region size and region availability. Show the denominator for each estimate. Check goal-probability reliability when per-bin sample sizes support it. Record the region construction, KDE settings if using a conditional mode, and the exact conditioning event.
- **Sampling and reproducibility.** Estimate model differences by paired bootstrap over shots, stratified by the locked strata. Resample physical shots as clusters when their noisy repeats share a trajectory. Use 2,000 bootstrap replicates and record the seed. For the supplied kick, repeat with a second seed and a doubled draw budget. The planned stability targets are 1 percentage point for event probabilities, 0.03 m for reported interval endpoints, and 0.10 m for the bandwidth-sensitive mode. If the targets fail, increase the budget or label the affected summaries as unstable. Report effective sample size where applicable.

Never infer a narrow interval or a stable mode from too few effective draws. Before unblinding, lock the minimum effective support for each conditional statistic and any decision to abstain from a point recommendation. Use the same policy on selection and blind cases. Log why a result is unavailable even when a method can still report probabilities.

## Model choice and blind reporting

Preregister B0–B2 as gravity-only, exact time-quadratic, and distance-domain baselines. Preregister M1–M3 as constant quadratic drag, added effective transverse force, and a literature-based Reynolds-dependent drag curve with effective transverse force. Use the common observation and event definitions. Wrap uncertain baselines in the same frame-noise assumptions and state the parameter model used to generate forecast draws. Keep deterministic baseline point estimates available. A distance-only model with no time output enters the spatial and event comparisons where supported. Mark its arrival-time statistic unavailable. Refit each M3 ball-type scenario and report it separately unless an external source justifies weights.

On the selection split, rank candidates by the prespecified weighted mean of their all-case failure-penalized Brier loss. Compare M1–M3 in complexity order, keeping the strongest eligible simpler comparator, including the strongest baseline. Adopt a richer candidate only if it meets the frozen coverage and technical-failure tolerances, lowers the overall score by at least the frozen practical gain and more than one paired bootstrap standard error, and exceeds no frozen degradation limit in any core stress stratum. For the first protocol freeze, use a proposed absolute Brier gain of 0.01, a maximum stress-stratum increase of 0.02, a 95% region undercoverage tolerance of 5 percentage points, and at most 1% entirely invalid forecasts. Record the final values and denominators before releasing selection truth. An unavailable calibration estimate leaves the complexity upgrade unconfirmed. If no richer candidate passes, retain the simpler model or report both without a superiority claim.

Lock the selected candidate and its simpler comparator before blind evaluation. Claim a confirmed aggregate improvement only if the observed blind score difference reaches the frozen practical gain, its paired 95% interval excludes zero, and the locked failure and stress checks pass. Otherwise report the comparison as inconclusive or unfavorable as supported and retain the simpler comparator as the conservative recommendation. Treat additional model changes as exploratory until retested on a fresh blind split.

For each results row retain the run ID, split, stratum, model ID, number of cases, true plane crossings, valid predictive distributions, physical outcome counts, technical failures, and point abstentions. Provide machine-readable estimates and the paired differences used in prose. Check missing-value semantics, complete case membership, and agreement with the event fixtures. Verify that event weights sum to one including failures, that radius clearance is a subset of `PLANE_GOAL`, and that \(P(G)=P(C)P(G\mid C)\) for positive plane mass when all draws classify. Pass the checked results to the figure and paper owners.
